# 模块四：interview-radar（真实中文面经锚定备考包）

> 来源：KunChen1110/InterviewRadar。强项是**抓真实中文面经 + 把题锚定到你简历的项目 + 强制不编造**。特化中文求职市场（牛客/小红书）。

## 1. 适用场景

用户说「帮我找 XX 岗位的真实面经」「预测面试官会怎么追问我的项目」「做个针对性备考包」。通常在 resume-optimization / llm-intern 之后用——简历定了，才锚得准。

## 2. 核心工作流

```
① 简历理解（抽项目、技能、技术栈）
② 种子查询（agent 用领域知识推检索词，优先底层技能词，不依赖预设词表）
③ 迭代检索（WebSearch 发现 URL → 分桶 → 收割 → 用收割词再检索，human-in-the-loop 纠偏）
④ 内容相关性判定
⑤ 抽题 + 语义决策（ExtractionDecision）
⑥ 去重排序 → ⑦ 项目锚定（FollowUpChain，is_grounded 判定）
⑧ 输出固定 10 节备考包
```

## 3. 方法论（质量铁律）

### 3.1 时效硬过滤

- 明确日期的帖只保留**近 730 天**；无日期的降权不优先。

### 3.2 排序规则

- 优先「**独立来源 URL 数 × 时效**」；出现次数只用来破平手。
- **≥2 个独立来源**才算「高频题」，避免单一帖误判。

### 3.3 项目锚定（核心差异）

- 每道高频题尝试挂到用户简历的某个项目；
- **追问链必须同时能追溯到（简历项目/技能）+（真实爬到的题）**，否则 `is_grounded=false`，当作通用八股题处理（不硬塞进项目）。
- 三层追问示例：该题→面试官可能追问 1（原理）→ 追问 2（你项目里怎么落地）→ 追问 3（边界/失败 case）。

### 3.4 可追溯优先于流畅度

- 绝不编造无溯源的题目；高频题只能来自 `ranked_questions.json`，证据 `excerpt` 可溯到 `raw_posts.json`。
- 输出备考包含「来源列表」一节，每题可点回原帖。

### 3.5 固定 10 节输出模板

定位 → Gap 分析 → 来源概览 → 高频题 → 追问链 → 自我介绍 → 冲刺计划 → 简历补强建议 → 来源列表 → 速查清单。

## 4. ⚠️ 依赖、前置与 ToS 风险（务必先告知用户）

- Python 3.11+ venv；小红书源需 **MediaCrawler + cookie/二维码登录**，**需翻墙**；OCR（RapidOCR）读小红书图片；GitHub/牛客走 connector 或 WebFetch。
- **ToS 风险**：自动抓取小红书/牛客可能违反对应平台服务条款，且涉及登录态。**用户已明确知晓并接受该风险**（套件合并时确认）。执行前仍可再次提醒，并建议：优先用公开的牛客/GitHub 面经，小红书抓取仅在用户坚持时启用。
- 绝不存储用户登录凭证到不应存的位置；抓取结果仅用于本人备考。

## 5. 红线

不编造面经；题目必须有可追溯来源；不把通用八股硬锚定到用户项目；遵守用户已接受的 ToS 风险边界，不擅自扩大抓取范围。
